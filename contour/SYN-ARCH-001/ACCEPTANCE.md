## 1. Требования, подлежащие трассировке

Всего **26** требований (INF-8, NFR-10, SEC-8).

| ID | Требование |
|---|---|
| INF-01 | Два ЦОД (ЦОД-1 «Основной», ЦОД-2 «Резервный»), ~38 км, каналы 2×10 Гбит/с, RTT ≤ 2 мс. Третьей площадки нет; доступны до 2 лёгких ВМ (4 vCPU / 8 ГБ) в «облачной зоне» банка, сетево независимой от обоих ЦОД (пригодны, например, для кворумных узлов) |
| INF-02 | В каждом ЦОД — два продуктивных кластера Kubernetes (совместимость с Platform V подтверждена пилотом), ОС узлов SberLinux OS Server. Под Synapse выделяется до 40 worker-узлов (16 vCPU / 64 ГБ) на кластер. Corax по системным требованиям разворачивается на отдельных хостах/ВМ (не в K8s) |
| INF-03 | PKI банка: корпоративный УЦ, выпуск x509; хранилище секретов — кластер HashiCorp Vault (3 узла, растянут между ЦОД) |
| INF-04 | Мониторинг: Prometheus + Zabbix; логи — централизованный сбор в SIEM; трейсинг — корпоративный Jaeger |
| INF-05 | Внешние потребители и партнёры подключаются через DMZ: L4/L7-балансировщики с health-check, DNS/GSLB для переключения между ЦОД |
| INF-06 | Команда: 3 интеграционных архитектора, 6 инженеров сопровождения (Kubernetes — средний уровень, Synapse — без опыта), 2 специалиста ИБ. Внедрение — только через корпоративный CI/CD и IaC |
| INF-07 | Миграционные окна — ночи выходных дней; для потоков класса A перевод только с подтверждённой процедурой отката ≤ 30 минут; одновременный перевод всех потоков («big bang») запрещён |
| INF-08 | Legacy-платформа (ACE + IBM MQ + Confluent) эксплуатируется до конца миграции; лицензии позволяют параллельную работу старого и нового контуров до 18 месяцев. Общий срок программы — 18 месяцев |
| NFR-01 | Доступность интеграционного слоя для потоков класса A — ≥ 99,95 % в операционное время (04:00–01:00 МСК) |
| NFR-02 | Пропускная способность MQ-канала — пик 3 200 сообщений/с, p99 доставки через шлюз ≤ 500 мс |
| NFR-03 | Пропускная способность событийного канала — среднее 12 000, пик 40 000 событий/с; retention критичных топиков ≥ 7 суток |
| NFR-04 | Потеря сообщений класса A — подтверждённые сообщения не теряются при отказе одного узла/пода (RPO = 0 внутри ЦОД); при потере ЦОД — RPO ≤ 30 с для событий, для MQ-потоков класса A — по регламенту DR (обосновать) |
| NFR-05 | RTO при потере ЦОД — класс A ≤ 15 мин, класс B ≤ 60 мин |
| NFR-06 | Файловый обмен — файлы до 2 ГБ, 4 ТБ/мес, подпись и контроль целостности |
| NFR-07 | Квотирование внешних потребителей — ограничение нагрузки от каждого внешнего потребителя; при потере ЦОД квоты не должны «схлопываться» или удваиваться |
| NFR-08 | Масштабирование — рост числа потоков +50 % за 2 года без перепроектирования топологии |
| NFR-09 | Миграция без остановки — перевод каждого потока без недоступности для его участников; откат потока ≤ 30 мин |
| NFR-10 | Тестирование — автоматизированная регрессия каждого мигрируемого потока до перевода; нагрузочное тестирование по профилю NFR-02/03 |
| SEC-01 | TLS для всех каналов; mTLS для межсервисных и межкомпонентных взаимодействий; сертификаты из корпоративного УЦ; ротация не реже раза в год без простоя |
| SEC-02 | Файлы с ПДн и банковской тайной — подпись и шифрование при передаче и хранении в промежуточном объектном хранилище |
| SEC-03 | Секреты подключений (пароли, ключи к внешним АС) — только во внешнем хранилище секретов банка (Vault); открытые пароли в конфигурациях запрещены |
| SEC-04 | Разграничение доступа к интеграциям и порталам по ролям; доступ разработчиков/администраторов — через корпоративный IdP (OIDC) |
| SEC-05 | Аудит операций с интеграциями и доступа к сообщениям; логи интеграционного слоя передаются в SIEM; администраторы слоя не могут изменить переданные журналы |
| SEC-06 | Изоляция интеграций по доменам банка (отдельные namespace/проекты); политики трафика на границах доменов — централизованные |
| SEC-07 | События с ПДн в событийном канале — сквозное шифрование (потребитель расшифровывает самостоятельно) |
| SEC-08 | Межсервисная аутентификация и авторизация во всех взаимодействиях интеграционного слоя |

Для каждого требования в итоговом документе должна быть строка
трассировки одного из видов:

```
<ID> -> <адрес в документе>          # раздел/подраздел, где требование закрыто
<ID> -> unverifiable: <причина>      # закрыть нельзя и объяснено почему
```

`unverifiable` без причины не засчитывается: это не статус, а отказ
от трассировки.

## 3. Hard-fail (итог ограничивается)

| ID | Правило |
|---|---|
| HF-01 | Вымышленные компоненты/функции Synapse/Corax поданы как факт (например, «Synapse ESB», «Synapse Queue Manager», «встроенный DLQ-движок ASGT») |
| HF-02 | Путаница ролей: шлюз (ASGT/KFGT/JDBC/SAPG) назван брокером или хранилищем сообщений, либо брокер (SMBX/Corax) назван шлюзом |
| HF-03 | Заявлен RPO = 0 («нулевая потеря сообщений») при потере ЦОД на каналах с асинхронной межкластерной репликацией (MM2) без оговорок и компенсирующих мер |
| HF-04 | План миграции — «big bang»: все 240 потоков одной волной, нет критериев перевода и отката отдельного потока (нарушение INF-07/NFR-09) |
| HF-05 | Отсутствует хотя бы один обязательный артефакт D1–D10 |
