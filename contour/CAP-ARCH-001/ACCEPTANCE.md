| NFR-12 | Расширение любого слоя — без простоя сервиса (документированные механизмы добавления узлов/брокеров/шардов) |

| SEC-03 | Доступ аналитиков к DataMarts — через RBAC и профили настроек `datamarts-safeguard` (READONLY-лимиты, правила токсичности); пользователь по умолчанию отключён |
| SEC-04 | Аудит административных операций всех слоёв выгружается в SIEM банка (без COTE, INF-06) |
| SEC-05 | Административные доступы персонализированы (PAM); разграничение прав на Radish — согласованная ACL-модель продукта |

Для каждого требования в итоговом документе должна быть строка
трассировки одного из видов:

```
<ID> -> <адрес в документе>          # раздел/подраздел, где требование закрыто
<ID> -> unverifiable: <причина>      # закрыть нельзя и объяснено почему
```

`unverifiable` без причины не засчитывается: это не статус, а отказ
от трассировки.

## 3. Hard-fail (итог ограничивается)

| ID | Правило |
|---|---|
| HF-01 | Вендорские НФТ выданы за **гарантированную** производительность на целевой конфигурации банка (например, «Corax выдержит 42 500 соб/с — вендор подтверждает 13 000 tps» или «Pangolin выдержит 35 000 TPS» как факт) — вопреки оговорке документации о необходимости НТ на целевой конфигурации |
| HF-02 | Аномальное значение «p99 = 1375 с» из НФТ Corax принято как валидный норматив/SLA **без** пометки «требует проверки у вендора» |
| HF-03 | Вымышленные компоненты/функции/числа продуктов поданы как факт (например: «Pangolin Proxy», «встроенный шардировщик Radish в один клик», несуществующие НФТ-таблицы Pangolin, «DataMarts штатно партиционирует таблицы по TTL» — последнее в съёме не раскрыто) |
| HF-04 | Хотя бы для одного из четырёх слоёв (Pangolin / Radish / Corax / DataMarts) отсутствует **численный расчёт ёмкости** (есть только декларации вида «масштабируется горизонтально») |
| HF-05 | Отсутствует хотя бы один обязательный артефакт D1–D10 |
