## 1. Требования, подлежащие трассировке

Всего **29** требований (INF-9, NFR-12, SEC-8).

| ID | Требование |
|---|---|
| INF-01 | Два ЦОД (ЦОД-1 «Основной», ЦОД-2 «Резервный»), ~40 км, 2×10 Гбит/с, RTT 1–3 мс. Третьей площадки нет; «облачная зона» банка, сетево независимая от обоих ЦОД: до 2 лёгких ВМ (4 vCPU / 8 ГБ RAM / 100 ГБ) |
| INF-02 | В каждом ЦОД до 10 новых хостов под контур: 16 CPU / 64 ГБ RAM / RAID10 NVMe 4 ТБ (XFS); ОС — только Platform V SberLinux OS Server 9.7; Java — SberJDK 17. Хосты под Pangolin уже выделены и в этот бюджет не входят |
| INF-03 | Развёртывание — только Ansible из корпоративного репозитория; ручные изменения конфигураций запрещены |
| INF-04 | S3-совместимое хранилище в обоих ЦОД (раздельные бакеты); NFS для архивов нет |
| INF-05 | Мониторинг — Zabbix + Prometheus-совместимый сбор; SIEM принимает события по HTTPS и из лог-файлов агентами. **Platform V Monitor (COTE) в банке не развёрнут |
| INF-06 | Хранилище секретов — **HashiCorp Vault** (3 узла между ЦОД, RTO ≤ 5 мин). SecMan отсутствует и не планируется |
| INF-07 | Команда: 2 инженера middleware (Corax — базово), 2 DBA Pangolin, 1 администратор ИБ; нагрузочное тестирование pipeline перед запуском обязательно |
| INF-08 | Окна на промышленной СУБД: 1 раз в квартал, ночь вс→пн, ≤ 4 часа, согласование за 3 недели. **Внеплановые рестарты лидера Pangolin запрещены** (переключения — только штатный `switchover` по регламенту) |
| INF-09 | Platform V GraDeLy в банке **не лицензирован**; бюджетный запрос на GDL возможен только с обоснованием на базе документированных характеристик |
| NFR-01 | Доступность сквозного pipeline (захват → топик → потребитель) — ≥ 99,9 % в год (24×7) |
| NFR-02 | Потеря подтверждённых CDC-событий при отказе брокера/СУБД-узла внутри ЦОД — 0 |
| NFR-03 | Сквозная задержка «коммит в Pangolin → событие у антифрода» — p99 ≤ 5 с при пике |
| NFR-04 | RPO при полной потере ЦОД-1 (событийный контур) — ≤ 5 мин (честно оценить и обосновать) |
| NFR-05 | RTO при полной потере ЦОД-1: pipeline восстановлен, включая возобновление CDC-захвата — ≤ 60 мин (ручные действия допустимы, runbook обязателен) |
| NFR-06 | Упорядоченность — строгий порядок событий в пределах счёта/договора, включая ретраи коннектора и ребалансировки потребителей; глобальный порядок не требуется |
| NFR-07 | Дубли у потребителей — финансовые эффекты применяются потребителями не более одного раза; границы гарантий зафиксированы явно |
| NFR-08 | Изоляция нагрузки — DWH- и аудит-контуры не деградируют доставку в антифрод более чем на 5 % |
| NFR-09 | Хранение — 7 дней онлайн в топиках; архив аудита 5 лет; восстановление потока на дату ≤ 24 ч |
| NFR-10 | Деградация при недоступности Corax — при недоступности брокера до 4 ч события не теряются, OLTP-контур АС «Карт-Процессинг» не останавливается и не деградирует (оценить бюджет WAL) |
| NFR-11 | Обновления и ротация сертификатов звеньев pipeline — без простоя (rolling) |
| NFR-12 | Ёмкость — 5 лет роста нагрузки +30 %/год + 30 % запас на дисках брокеров |
| SEC-01 | TLS не ниже 1.2 (рекомендовано 1.3) на всех каналах pipeline: Pangolin ↔ CDC-звено, CDC-звено ↔ Corax, брокеры ↔ брокеры, Schema Registry/UI, мониторинг |
| SEC-02 | Аутентификация всех участников; персональный принципал на сервис; анонимный доступ запрещён (включая Schema Registry и Corax UI) |
| SEC-03 | Минимальные права: ТУЗ CDC-захвата на Pangolin — без superuser (либо явное обоснование и компенсирующие меры); ACL в Corax с минимальными правами на топики/группы; wildcard-административные ACL для сервисов запрещены |
| SEC-04 | Аудит всех административных операций над pipeline (топики, ACL, конфигурации, квоты, схемы) с выгрузкой в SIEM банка |
| SEC-05 | ПДн и данные карт в событиях защищаются сквозным шифрованием: администратор платформы и обладатель архива S3 не читают содержимое без ключей |
| SEC-06 | Пароли/секреты в конфигурациях — только зашифрованные; ключи — в Vault банка; дефолтные пароли инсталляторов заменяются |
| SEC-07 | Ротация сертификатов не реже раза в год, без недоступности pipeline |
| SEC-08 | Доступ администраторов персонализированный; их действия попадают в аудит (SEC-04) |

Для каждого требования в итоговом документе должна быть строка
трассировки одного из видов:

```
<ID> -> <адрес в документе>          # раздел/подраздел, где требование закрыто
<ID> -> unverifiable: <причина>      # закрыть нельзя и объяснено почему
```

`unverifiable` без причины не засчитывается: это не статус, а отказ
от трассировки.

| ID | Артефакт |
|---|---|
| D1 | Резюме решения для руководства (≤ 15 строк) |
| D2 | Схема сквозного pipeline (текстовая: Mermaid или PlantUML): кластер Pangolin (лидер/реплики, DCS, Pooler), CDC-звено, кластеры Corax (брокеры, координация, Schema Registry, UI, Mirror Maker 2), потребители, S3-архив, оба ЦОД и направления потоков |

| D4 | Гарантии доставки и ordering end-to-end: конфигурация продюсера/топиков/потребителей, ключи и партиции, стыковка двух моделей порядка, дедупликация, явные границы гарантий |

| D7 | Контур безопасности: каналы, аутентификация, минимальные права ТУЗ CDC, ACL, аудит в SIEM, e2e-шифрование ПДн/PAN, секреты, ротация сертификатов |
| D8 | Производительность и ёмкость: расчёты партиций/брокеров/дисков/канала из нагрузки, квоты потребителей, влияние CDC на источник |
| D9 | Таблица трассировки требований → решения |
| D10 | Реестр допущений, рисков, открытых вопросов к вендору и отвергнутых альтернатив |

## 3. Hard-fail (итог ограничивается)

| ID | Правило |
|---|---|
| HF-01 | pgcopydb `follow` предложен как промышленный CDC-механизм вопреки документированным ограничениям: заявлено, что follow переживает рестарт БД, работает с TDE (в сценарии TDE включена), либо не требует superuser на приёмнике; либо follow назначен основным CDC без явной огласки этих ограничений |
| HF-02 | Строгий **глобальный** порядок событий (по всему топику / всем счетам) заявлен как штатно достижимый, либо требование ordering по счёту «закрыто» без ключей сообщений и партиционирования |
| HF-03 | Заявлен RPO = 0 при потере ЦОД-1 для событийного контура при асинхронной межкластерной репликации (MM2), либо MM2 назван синхронным механизмом |
| HF-04 | Вымышленные компоненты/функции поданы как факт (например: «штатный CDC-коннектор Corax для Pangolin», «GraDeLy входит в состав Corax или Pangolin», «Records Policy входит в Apache Kafka», «встроенный балансировщик Corax для клиентов») |
| HF-05 | Отсутствует хотя бы один обязательный артефакт D1–D10 |
