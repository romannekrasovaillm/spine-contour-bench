Файл **только для чтения**: он заморожен до прогона (sha256 в
`prereg.lock.json`) и одинаков для всех рук. Собран из файлов авторов

## 1. Требования, подлежащие трассировке

Всего **29** требований (INF-8, NFR-12, SEC-9).

| ID | Требование |
|---|---|
| INF-01 | Два ЦОД (ЦОД-1 «Основной», ЦОД-2 «Резервный»), расстояние ~40 км, выделенные каналы 2×10 Гбит/с, RTT между ЦОД 2–3 мс. Третьей площадки **нет**; есть возможность разместить до 2 лёгких ВМ (4 vCPU / 8 ГБ) в «облачной зоне» банка, сетево независимой от обоих ЦОД |

| INF-03 | Хранилище секретов банка — кластер **HashiCorp Vault 1.15.x** (3 узла, растянут между ЦОД). SecMan в банке не развёрнут. Сторонние KMS-эмуляторы в промышленной среде запрещены политикой ИБ |
| INF-04 | СРК банка предоставляет S3-совместимое и NFS-хранилище в каждом ЦОД; требуется интеграция через штатные средства СУБД |
| INF-05 | Мониторинг — **Zabbix**; журналирование — централизованный SIEM; управление привилегированным доступом — **PAM-система** (все административные сессии только через PAM) |
| INF-06 | Кластер серверов 1С: 6 рабочих серверов в ЦОД-1 (active), 3 резервных сервера 1С в ЦОД-2 (standby, включаются при DR). Лицензии 1С на обе площадки имеются |

| SEC-03 | Разделение обязанностей: включение шифрования, изменение состава расширений, выдача доступа к защищаемым объектам требуют участия администратора ИБ |
| SEC-04 | Все административные подключения — персонализированные, через PAM; прикладной доступ кластера 1С — только через ТУЗ информационных баз; при исчерпании пула соединений служебные учётные записи СУБД должны сохранять доступ к БД |
| SEC-05 | Аудит событий безопасности (в т.ч. по требованиям ГОСТ Р 59548-2022) с выгрузкой в SIEM; аудит подключений через пулер; маскирование параметров запросов в журналах |
| SEC-06 | TLS для всех соединений (кластер 1С ↔ пул ↔ СУБД, узлы кластера ↔ DCS, REST API оркестратора); сертификаты из корпоративного УЦ, ротация не реже раза в год без простоя |
| SEC-07 | Парольные политики для локальных УЗ (сложность, срок действия, история); аутентификация административных пользователей СУБД через LDAP-каталог банка |
| SEC-08 | Резервные копии не должны позволять восстановить открытые данные без ключей из хранилища секретов |

Для каждого требования в итоговом документе должна быть строка
трассировки одного из видов:

```
<ID> -> <адрес в документе>          # раздел/подраздел, где требование закрыто
<ID> -> unverifiable: <причина>      # закрыть нельзя и объяснено почему
```

`unverifiable` без причины не засчитывается: это не статус, а отказ
от трассировки.

## 3. Hard-fail (итог ограничивается)

| ID | Правило |
|---|---|
| HF-01 | Решение внутренне противоречиво по редакции: выбрана редакция Standard / Standard для ERP-систем, но используются Enterprise-only функциональности (TDE, защита от привилегированных пользователей, автопартиционирование, глобальные индексы, LDAP-авторизация, pgloader/pgcopydb, оптимизация временных таблиц) — без явного обнаружения противоречия и пересмотра |
| HF-02 | Заявлено, что режим поддержки 1С не влияет на планировщик/производительность и/или рекомендовано его глобальное включение «на всякий случай» для смешанных (1С + не-1С) контуров; либо **вымышлен механизм/параметр** включения режима (GUC, флаг, опция инсталлятора, которых нет в CONTEXT — пробел §1.11) |
| HF-03 | Предложен **автоматический** promote standby-кластера при двух ЦОД без разбора документированного ограничения (ЦОД-2 не отличает сбой ЦОД-1 от сетевого разделения; promote — ручной, со STONITH, удалением секции `standby_cluster`), либо заявлен RPO = 0 при потере ЦОД-1 на асинхронной standby-репликации |
| HF-04 | Пул под кластер 1С предложен в `pool_mode = session` вопреки явной нерекомендации вендора без обоснования, либо конфигурация несостоятельна: клиентские соединения кластера 1С (3 400) не согласованы с `max_connections` (стартовая формула даёт GREATEST(5×64, 100) = 320), пулер отсутствует и прямое подключение 3 400 сессий не разобрано |
| HF-05 | Вымышленные компоненты/функции поданы как факт: «Pangolin 1C Gateway», «нативная поддержка управляемых блокировок 1С в ядре СУБД», «pgloader мигрирует с Oracle», «pgcopydb работает с источника Oracle», «ora2pg в 8.2.0 установлен по умолчанию», «Citus — поддерживаемый штатный сценарий шардирования Pangolin» |
| HF-06 | Отсутствует хотя бы один обязательный артефакт D1–D10 |
