Для каждого требования в итоговом документе должна быть строка
трассировки одного из видов:

```
<ID> -> <адрес в документе>          # раздел/подраздел, где требование закрыто
<ID> -> unverifiable: <причина>      # закрыть нельзя и объяснено почему
```

`unverifiable` без причины не засчитывается: это не статус, а отказ
от трассировки.

## 3. Hard-fail (итог ограничивается)

| ID | Правило |
|---|---|
| HF-01 | Кворум DCS не переживает потерю одной площадки: предложен 1 узел DCS, чётное число узлов, либо размещение, при котором потеря одного ЦОД оставляет меньшинство (например, 2+1 по двум ЦОД без третьей площадки, или все узлы в ЦОД-1/ЦОД-2) — **без** явного обоснования и компенсирующих мер (например, осознанный отказ от автоматического failover при потере ЦОД с пересмотром NFR-05) |
| HF-02 | Предложено **автоматическое** повышение standby-кластера при потере ЦОД (документация: «автоматическое повышение невозможно»), либо ручное повышение резервного кластера без обязательного STONITH исходной площадки, либо повышение через `pg_ctl promote` вместо удаления секции `standby_cluster` из динамической конфигурации |
| HF-03 | Заявлен RPO = 0 при потере ЦОД при **асинхронной** межплощадочной репликации, либо RPO = 0 при потере ЦОД без указания режима репликации между ЦОД вообще |
| HF-04 | Вымышленные компоненты или функции Pangolin поданы как факт: «Pangolin Witness», «Pangolin Proxy», «Pangolin Arbiter» как отдельный продукт/пакет (документированная роль — «узел арбитра», часть Pangolin Manager + DCS), «автоматический promote standby-кластера средствами Manager», «встроенный балансировщик Pangolin для маршрутизации на лидера» и т.п. |
| HF-05 | На площадке-3 размещён узел с данными (экземпляр СУБД, реплика) вопреки INF-01, либо на площадке-3 размещены ключи TDE/секреты, достаточные для расшифровки данных, вопреки SEC-06 — без явной пометки о нарушении политики ИБ |
| HF-06 | Отсутствует хотя бы один обязательный артефакт D1–D10 |
