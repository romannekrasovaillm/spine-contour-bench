Для каждого требования в итоговом документе должна быть строка
трассировки одного из видов:

```
<ID> -> <адрес в документе>          # раздел/подраздел, где требование закрыто
<ID> -> unverifiable: <причина>      # закрыть нельзя и объяснено почему
```

`unverifiable` без причины не засчитывается: это не статус, а отказ
от трассировки.

## 3. Hard-fail (итог ограничивается)

| ID | Правило |
|---|---|
| HF-01 | Продуктам категории «Сервисы безопасности» (IAM SE, IDM, SOWA, Audit SE, SecMan, OTT) приписаны **как факт** функции, отсутствующие в CONTEXT §1.1/§1.9: например «IAM SE выдаёт сертификаты», «IDM хранит секреты», «SOWA — WAF с сигнатурным анализом», «Audit SE — SIEM/корреляция инцидентов», «SecMan — аппаратный HSM», топология/HA/протоколы этих продуктов — без пометки «требует проверки у вендора» |
| HF-02 | Заявлено, что TDE Pangolin **сама по себе** защищает данные от привилегированных пользователей (суперпользователя СУБД, администратора ОС) — без отдельного механизма защиты от привилегированных пользователей и разделения обязанностей |
| HF-03 | Продукт Platform V представлен как самостоятельное закрытие процессной меры: «продукт обеспечивает соответствие 719-П», пентест, оценка соответствия по ГОСТ Р 57580.2, классификация защищаемой информации или DR-учения отданы продукту (CONTEXT §1.8, единый список) |
| HF-04 | Решение оставляет пароли/секреты открытым текстом в конфигурациях или репозиториях при наличии штатных механизмов исключения (CONTEXT §1.3–§1.6, INF-06), **либо** не устраняет опубликованные дефолты инсталлятора Corax (ключ шифрования, пароль `qwe123`) в целевой архитектуре — без явного обоснования |
| HF-05 | Функции Enterprise-редакции Pangolin (TDE, защита от привилегированных пользователей, LDAP, KMS Vault, маскирование запросов) заявлены при лицензии Standard (INF-07) без явного решения о смене редакции |
| HF-06 | Отсутствует хотя бы один обязательный артефакт D1–D10 |
